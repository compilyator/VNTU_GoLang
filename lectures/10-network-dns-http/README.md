# Лекція 10: HTTPBingo та перевірки HTTP-клієнта

Початковий набір — [10-http.zip](https://github.com/compilyator/VNTU_GoLang/raw/refs/heads/main/lectures/10-network-dns-http/downloads/10-http.zip). [Контрольна сума SHA-256](https://github.com/compilyator/VNTU_GoLang/raw/refs/heads/main/lectures/10-network-dns-http/downloads/SHA256SUMS.txt). Задачник отримайте від викладача.

## Середовище

Потрібні Go **1.25.0 або новіший**, curl, Windows із PowerShell або Linux/macOS із Bash. Для задач 21–40 потрібен VS Code із [REST Client, humao.rest-client](https://marketplace.visualstudio.com/items?itemName=humao.rest-client). Інсталяцію Go та налаштування редактора шукайте в матеріалах свого курсу в Google Classroom за посиланням від викладача.

Основний сервіс — [HTTPBingo](https://httpbingo.org/), готова реалізація [go-httpbin](https://github.com/mccutchen/go-httpbin). Публічні запити не потребують реєстрації. Використовуйте лише вигадані дані; сервіс може відбивати Authorization, Cookie та тіло у відповіді. Не надсилайте справжніх секретів. Запити виконуйте по одному, без навантажувальних циклів; у разі 429 або недоступності припиніть повторення й використайте локальний варіант.

Закріплена версія локального go-httpbin — **v2.25.0**, сумісна з Go 1.25; це свідомий вибір, а не твердження про найновіший реліз. Зовнішня інсталяція цієї залежності потрібна один раз; її контрольні суми містить go.sum. Для роботи повністю без мережі завчасно виконайте go mod download.

Документацію сервісу, [версію v2.25.0](https://github.com/mccutchen/go-httpbin/tree/v2.25.0) і [синтаксис REST Client](https://github.com/Huachao/vscode-restclient) перевірено 12.11.2026. Публічний сервіс може змінюватись: перевіряйте суттєві поля, а не повний знімок відповіді.

## Завантаження та запуск

Збережіть ZIP і SHA256SUMS.txt поряд. Порівняйте суму перед розпакуванням.

PowerShell:

```powershell
Get-FileHash ./10-http.zip -Algorithm SHA256
Get-Content ./SHA256SUMS.txt
Expand-Archive -LiteralPath ./10-http.zip -DestinationPath ./task-10
Set-Location ./task-10/10-http
go mod download
go run ./cmd/demo
```

Bash (Linux):

```bash
sha256sum -c SHA256SUMS.txt
mkdir task-10
unzip 10-http.zip -d task-10
cd task-10/10-http
go mod download
go run ./cmd/demo
```

На macOS замість sha256sum використайте `shasum -a 256 -c SHA256SUMS.txt`. Каталог task-10 має бути новим; якщо він існує, оберіть іншу назву. Очікуваний stdout демонстраційної заглушки — `READY` та LF, код завершення 0. Це лише перевірка запуску, не готовий HTTP-клієнт.

Позначення **K** у задачнику — корінь 10-http, **F** — його fixtures. Для незалежних реалізацій створюйте окремі пакети в K. Імпорти починаються з `example.com/course/http10/`. Запускайте `go test ./... -timeout 30s` із K. Початкове повідомлення `[no test files]` не доводить правильності студентських програм: власні тести ще треба написати.

## Три способи виконання запитів

1. **Задачі 5–20:** команди в задачнику. PowerShell використовує саме curl.exe, Bash — curl. Частина вправ про URL запускає cmd/urlinfo без мережі. Команди go run повертають код оболонки 1 для невдалої програми й додаткове повідомлення go; для точного коду 2 зберіть утиліту через go build і запустіть її без go run.
2. **Задачі 21–40:** відкрийте K як каталог у VS Code, потім requests.http. На початку задано `@base = https://httpbingo.org`. Знайдіть task21 тощо й натисніть **Send Request** над одним запитом. Директиви `# @no-redirect` та `# @no-cookie-jar` показують початкову відповідь і не дають іншим вправам непомітно змінювати cookie. POST читає demo.txt із файла, щоб не додати зайвий LF.
3. **Від 41:** власний Go-клієнт. Один позитивний приклад перевірте на публічному сервісі; автоматичні повтори, лічильники запитів, помилки та TLS перевіряйте локально через lab. Для публічного Client задайте timeout 10 s, локальний Client має 3 s; умови задач на timeout перевизначають це значення.

Відповіді HTTPBingo мають динамічні origin, url із базовою адресою, Date та службові заголовки. Не фіксуйте IP, порядок JSON-полів, службові заголовки або точний текст мережевої помилки. Умови наводять вибрані поля або результат власної програми, а не завжди повний body. `args` і `headers` у JSON HTTPBingo — об’єкти з масивами рядків. Реальний HTTP-заголовок у Go читається через http.Header, це інший об’єкт.

## Запасний локальний запуск готового сервера

В окремому терміналі PowerShell або Bash виконайте ту саму команду:

```text
go run github.com/mccutchen/go-httpbin/v2/cmd/go-httpbin@v2.25.0 -host 127.0.0.1 -port 18080
```

Залиште термінал відкритим. Для зупинки натисніть Ctrl+C. Якщо порт зайнятий, виберіть інший, наприклад 18081; не завершуйте чужий процес. У командах curl замініть базову адресу на http://127.0.0.1:18080, у requests.http — значення @base. У Go передайте цю адресу як base. Локальний HTTP — навчальний виняток лише для loopback; публічний сервіс використовується через HTTPS.

Початкове завантаження Go-модуля потребує інтернету. Якщо DNS/проксі/сертифікат публічного сервісу спричинив відмову, це ще не доводить помилку вашого алгоритму. Збережіть клас відмови й повторіть на локальному сервері. Перевірку TLS не вимикайте.

## Назви навчальних відповідей

`URL("record")` у задачнику — **скорочення**, а не вигаданий шлях /record. Повна адреса обчислюється так:

```go
target := endpoints.URL(endpoints.Public, "record")
// target — https://httpbingo.org/base64/...?... зі справжнім маршрутом.
```

HTTPBingo /base64 декодує задані нами навчальні байти; query content-type задає тип відповіді. Готові адреси містить paths.json та пакет endpoints, відповідні точні тіла — fixtures. Студент не має самостійно реалізувати Base64. Стандартний /json сервісу містить slideshow; **це не Record**.

| Назва | Тіло або маршрут |
|---|---|
| record | {"name":"Оля","score":80} |
| record-charset | Та сама Record; Content-Type із charset=utf-8 |
| text | ok та LF |
| bad-json | {broken |
| bad-record | Record з score=101 |
| two-json | Два об’єкти Record поспіль |
| unknown-json | Record із додатковим extra=1 |
| records | Масив Оля/80, Іра/90 |
| sample | {"args":{"topic":"http"}} без LF |
| echo | /anything |
| html | /html |
| empty | /status/204 |
| bytes8, bytes9 | /bytes/8?seed=1, /bytes/9?seed=1 |
| stream9 | /stream-bytes/9?seed=1&chunk_size=3 |
| slow | /delay/2 |

Record використовується лише для строгого навчального API: поля name і score, ім’я 1–20 кодових точок Unicode без CR/LF, score від 0 до 100. Власний тип оголосіть із відповідними JSON-тегами. Рівно один JSON-документ, без невідомих полів; за помилки не повертайте частково прийняту модель. Для echo-моделі, навпаки, додаткові службові поля дозволені.

## Готові локальні перевірки без написання сервера

lab запускає go-httpbin у httptest і автоматично закриває його після тесту. Кожен Start отримує новий порт. Це той самий готовий HTTP-стенд, додатково обгорнутий лічильником запитів.

```go
package client_test

import (
    "testing"
    "example.com/course/http10/lab"
)

func TestClient(t *testing.T) {
    s := lab.Start(t, false)
    target := s.URL("record")
    // Передайте s.Client і target власній функції.
    _ = target
    // s.Handler.Requests() повертає копію записів Method, Path.
}
```

Цей шаблон лише готує середовище: додайте виклик і перевірки, інакше тест нічого не доводить. Для звичайного маршруту використайте `s.BaseURL + "/status/404"`. Для TLS — `lab.Start(t,true)` і саме `s.Client`, який довіряє тестовому сертифікату. Не встановлюйте InsecureSkipVerify.

`lab.StartPair(t,firstTLS)` повертає два незалежні сервери. Лише локальна обгортка має /test/cross (redirect на другий сервер) та /test/loop (цикл). На публічний сервіс ці маршрути не надсилайте. Лічильник не записує query, headers або body. Схема, hostname і явний port визначають дозволений origin; userinfo заборонено. MaxRedirects — кількість переходів після початкового запиту, діапазон 0–5.

Скасований context — сигнал припинити операцію. Для відповідної вправи підготуйте:

```go
ctx, cancel := context.WithCancel(context.Background())
cancel()
req, err := http.NewRequestWithContext(ctx, http.MethodGet, target, nil)
// Перевірте err, потім передайте req вашому клієнту.
```

Це готовий мінімум для задачі; системний розгляд context буде пізніше. Тест timeout має зовнішню межу, не порівнює час до мілісекунди.

## Підміни транспорту та тіла

testio.Stub реалізує http.RoundTripper. Створіть `&http.Client{Transport:stub, Timeout:time.Second}`; у stub задайте Status, Header, Body або Err. Calls рахує звернення. Для нової відповіді створюйте новий Stub і нове Body — закрите тіло не використовується повторно.

TrackBody.Data — байти; FinalEOF повертає останні байти разом з EOF; Fail і FailAfter відтворюють помилку читання після заданої кількості байтів. ReadBytes, Closed та CloseCalls дозволяють перевірити ресурс. FailAfter має бути невід’ємним. ErrTransport, ErrRead, ErrWrite — контрольовані помилки для errors.Is; Client.Do може обгорнути їх у url.Error.

Власна ReadBodyLimited/Fetch відхиляє limit поза 0–4096 до HTTP-запиту. Якщо функція вже отримала Body у власність, вона закриває його і при неправильному ліміті. На відмові читання чи перевищенні ліміту результат nil,error. Не плутайте EOF із втратою останніх n>0 байтів.

brokenquery, brokenlimit, brokenredirect — **навмисно несправні програми** для останніх трьох задач. Вони компілюються; правильність визначає контракт задачі. Спочатку напишіть тести, відтворіть відмову, знайдіть причину й виправте її. Готових розв’язків у наборі немає.

## Порядок роботи та LLM

Спочатку власна спроба, потім один успішний і один граничний або помилковий випадок. Для невеликої задачі достатньо коду, команди або тесту та фактичного результату; великий звіт на кожну вправу не потрібен.

Онлайн-LLM доречна для пояснення протоколу й пошуку контрприкладу: попросіть перевірити власну гіпотезу без готового розв’язку, звірте її з документацією та самостійно відтворіть результат. Агент доречний для роботи з локальними тестами: дозвольте зміни тільки у власній копії K, без реальних секретів, сторонніх адрес або навантажувальних запитів. Перегляньте кожну зміну.

Ведіть один стислий журнал: сервіс/інструмент, модель якщо відома, дата, мета, суттєвий запит, використаний результат, ваші виправлення та спосіб перевірки. Відповідь LLM і один контрольний приклад не є доказом загальної коректності.
