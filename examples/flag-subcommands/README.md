# Приклад `flag-subcommands`: підкоманди та прапорці

Приклад реалізує маленьку CLI-утиліту з командами `length`, `version` і `help`. Його мета — показати розбір аргументів, окремий `flag.FlagSet`, потоки виведення та коди завершення.

> **Основна інструкція:** приклад супроводжує матеріал [«Аргументи командного рядка та підкоманди в Go»](../../manuals/go-cli-flag/). В інструкції докладніше розглянуто `os.Args`, обов’язкові параметри, `FlagSet.Visit`, залишкові аргументи, довідку, потоки, коди завершення та перевірку CLI.

## Структура

```text
flag-subcommands/
├── README.md
├── main.go
└── main_test.go
```

Ключові частини `main.go`:

- `main` передає `os.Args[1:]`, `os.Stdout` і `os.Stderr` у `run`;
- `run` вибирає підкоманду;
- `runLength` створює окремий `flag.FlagSet` і перевіряє залишкові аргументи;
- `convertLength` містить предметне обчислення без залежності від консолі;
- `printUsage` формує коротку довідку.

Функція `run` повертає код, а не викликає `os.Exit`. Лише `main` завершує процес. Завдяки цьому тести можуть викликати CLI-логіку без запуску окремої програми.

## Запуск

Усі команди виконуйте з каталогу `examples`.

Показати довідку:

```powershell
go run ./flag-subcommands help
```

Показати версію:

```powershell
go run ./flag-subcommands version
```

Перетворити сантиметри на метри:

```powershell
go run ./flag-subcommands length -value 250 -from cm -to m
```

Очікуваний результат:

```text
250.00 cm = 2.50 m
```

Прапорці можна записувати і з подвійним дефісом: `--value`, `--from`, `--to`.

## Помилкові сценарії

```powershell
go run ./flag-subcommands
go run ./flag-subcommands unknown
go run ./flag-subcommands length -value 2
go run ./flag-subcommands length -value -1 -from m -to cm
go run ./flag-subcommands length -value 2 -from km -to m
```

У цих випадках повідомлення потрапляє до `stderr`, а процес повертає ненульовий код. PowerShell зберігає код зовнішньої програми в `$LASTEXITCODE`; Bash і zsh — у `$?`.

## Тести

```powershell
go test -v ./flag-subcommands
```

Тест використовує `bytes.Buffer` окремо для `stdout` і `stderr`, а також перевіряє код повернення. Набори аргументів задаються як `[]string`, тому тест не залежить від оболонки.

## Важливе обмеження прикладу

`-value` має значення за замовчуванням `0`, тому поточний приклад не відрізняє відсутній прапорець від явно переданого нуля. У лабораторній, де параметр обов’язковий, факт його передавання треба перевірити через `FlagSet.Visit`, як описано в пов’язаній інструкції.

## Експерименти

1. Додайте тест команди `version`.
2. Додайте тест зайвого позиційного аргументу.
3. Реалізуйте перевірку явної наявності `-value` через `Visit`.
4. Додайте нову нейтральну підкоманду, не змішуючи її прапорці з `length`.
5. Порівняйте текст у `stdout` і `stderr` для успішного та помилкового запусків.

## Типові помилки

- передавання до `run` повного `os.Args` разом з ім’ям програми;
- використання глобального `flag.CommandLine` для всіх підкоманд;
- виклик `os.Exit` усередині функції, яку треба тестувати;
- ігнорування `flags.Parse`, `flags.NArg()` або помилки перетворення;
- змішування звичайного результату та діагностики в одному потоці.
