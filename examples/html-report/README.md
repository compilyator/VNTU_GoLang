# HTML-звіт про обладнання

Самостійний приклад: JSON із вигаданими даними → перевірка → обчислення → HTML-шаблон → окремий файл. Покрокове пояснення — в [інструкції](../../manuals/go-html-reports/README.md).

## Файли

- [main.go](main.go) — читання, перевірка, модель представлення, рендеринг і запис;
- [data/sample.json](data/sample.json) — тестовий набір;
- [report.tmpl.html](report.tmpl.html) — шаблон із вбудованими CSS і необов’язковою кнопкою друку;
- [sample-report.html](sample-report.html) — готовий зразок для локального відкриття;
- [main_test.go](main_test.go) — перевірки чисел, екранування та помилок.

## Середовище й запуск

Go 1.25.0 або новіший сумісний випуск, браузер. Сторонніх залежностей немає, тому `go.sum` не потрібний. Приклад входить до спільного модуля `examples`; окремий `go.mod` не потрібний. Перевірено 21.09.2026: Windows, PowerShell, Go 1.25.1.

У каталозі `examples/html-report`, PowerShell або Bash:

```text
go test -v ./...
go vet ./...
go run . --input data/sample.json --template report.tmpl.html --output report.html
```

Відкрийте `report.html` у браузері. Очікування: **3 найменування, 15 одиниць, 2 позиції для поповнення**. Час формування залежить від запуску, час спостереження — від JSON.

Для нового звіту задайте новий шлях: наявні файли не перезаписуються. Шляхи відлічуються від поточного каталогу. Повторний запуск із тим самим виходом має завершитися помилкою без зміни файла. Немає підкоманд чи додаткового роздільника `--` перед прапорцями.

## Межі прикладу

Один довірений шаблон і один JSON до 1 MiB; 1–100 позицій, кількості 0–10000. Пропущені числа та `null` відхиляються, нуль дозволений. Невідомі поля й додаткові JSON-документи відхиляються; окремої перевірки повторюваних ключів немає. Це демонстрація шаблонізації, а не готова реалізація лабораторної з режимами й предметною статистикою.

Шаблон є кодом: перевіряйте його CSS/JS. JSON передається звичайними значеннями через `html/template`. Основний зміст не залежить від мережі чи JavaScript. Буфер і створення нового файла не гарантують відновлення після аварійного вимкнення живлення.

## Власна практика та LLM

У копії набору замініть кількість мультиметрів із 3 на 5. До запуску обґрунтуйте очікування: 17 одиниць і 1 позиція для поповнення. Згенеруйте новий HTML і перевірте числа. Попросіть онлайн-LLM запропонувати два варіанти відображення дефіциту, оберіть один і поясніть вибір. Для агента обмежте доступ власною копією прикладу, перегляньте diff і повторіть тести. У журналі зазначте сервіс, модель, якщо відома, дату, запит, прийнятий результат, власні зміни й спосіб перевірки.
