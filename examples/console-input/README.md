# Приклад `console-input`: читання та валідація введення

Приклад читає два рядки: кількість від 1 до 10 і непорожню назву. Він демонструє розділення читання, перетворення тексту й перевірки значень, а також тестування без реальної клавіатури.

> **Основна інструкція:** цей приклад є практичним доповненням до матеріалу [«Консольне введення і валідація в Go»](../../manuals/go-console-input/). Якщо ви прийшли безпосередньо до коду, зверніться до інструкції за поясненням `bufio.Scanner`, `strconv.Atoi`, перевірки діапазонів, повторного введення, потоків і негативних сценаріїв.

## Структура

```text
console-input/
├── README.md
├── main.go
└── main_test.go
```

- `request` об’єднує вже перевірені значення `Count` і `Label`.
- `readRequest(io.Reader)` читає рівно два рядки й повертає структуру або помилку.
- `scanError` відрізняє помилку джерела даних від передчасного завершення введення.
- `main` під’єднує функцію до `os.Stdin`, `os.Stdout` і `os.Stderr`.
- `main_test.go` передає підготовлений текст через `strings.NewReader`.

## Послідовність обробки

```text
io.Reader → Scanner → TrimSpace → Atoi → перевірка діапазону
          → наступний рядок → TrimSpace → перевірка порожнього значення
```

Текстова назва читається цілим рядком, тому може містити пробіли. `strings.TrimSpace` видаляє пробіли на краях, але не руйнує пробіли всередині назви.

## Інтерактивний запуск

Із каталогу `examples`:

```powershell
go run ./console-input
```

Після запрошення введіть, наприклад:

```text
3
Калібрувальний набір
```

Очікуваний результат:

```text
Прийнято: count=3, label="Калібрувальний набір"
```

## Неінтерактивний запуск

PowerShell:

```powershell
"3`nКалібрувальний набір`n" | go run ./console-input
```

Bash або zsh:

```bash
printf '3\nКалібрувальний набір\n' | go run ./console-input
```

Не використовуйте конвеєр як заміну власній перевірці інтерактивного режиму; це лише спосіб швидко повторити однаковий сценарій.

## Тести

```powershell
go test -v ./console-input
```

Таблиця тестів охоплює:

- коректну багатослівну назву;
- текст замість числа;
- число поза діапазоном;
- назву лише з пробілів;
- відсутній другий рядок.

У тестах немає випадкових даних або читання клавіатури. Кожен вхід записано статично, тому збій легко відтворити.

## Експерименти

1. Перевірте значення `1`, `10`, `0` і `11`.
2. Введіть назву з пробілами на початку та в кінці.
3. Додайте тест для порожнього введення.
4. Змініть дозволений діапазон і спочатку оновіть очікування в тестах.
5. Поясніть, чому `readRequest` приймає `io.Reader`, а не використовує `os.Stdin` напряму.

## Типові помилки

- змішування `fmt.Scan` і читання повного рядка без розуміння залишкового символу нового рядка;
- виклик `strconv.Atoi` без перевірки помилки;
- перевірка діапазону до успішного перетворення;
- приймання рядка, що складається лише з пробілів;
- залежність тесту від ручного введення.
