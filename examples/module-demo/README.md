# Приклад `module-demo`: власний пакет у Go-модулі

Приклад демонструє, як програма з `package main` використовує функцію з окремого локального пакета. Предметна дія навмисно проста — створення привітання — щоб увага залишалася на структурі модуля, імпорті та перевірці помилок.

> **Основна інструкція:** цей приклад доповнює матеріал [«Go-модулі та підключення пакетів»](../../manuals/go-modules/). Якщо ви відкрили приклад напряму, спочатку або паралельно ознайомтеся з інструкцією: у ній пояснено різницю між модулем, пакетом і репозиторієм, вибір назви, структуру `go.mod`, import path та типові помилки.

## Що тут показано

- один Go-модуль може містити кілька пакетів;
- import path складається з назви модуля в `go.mod` і шляху до каталогу пакета;
- ідентифікатор із великої літери (`Build`) доступний іншому пакету;
- пакет може перевіряти дані й повертати результат разом із помилкою;
- тест бібліотечного пакета запускається разом з усіма іншими тестами модуля.

## Структура

```text
module-demo/
├── README.md
├── main.go
└── greeting/
    ├── greeting.go
    └── greeting_test.go
```

- `main.go` викликає `greeting.Build`, перевіряє помилку й друкує результат.
- `greeting/greeting.go` містить пакет `greeting` та експортовану функцію `Build`.
- `greeting/greeting_test.go` перевіряє очищення пробілів і сформоване повідомлення.
- Спільний для прикладів `go.mod` розташований на один рівень вище, у каталозі `examples`.

Import path має вигляд:

```go
import "github.com/compilyator/VNTU_GoLang/examples/module-demo/greeting"
```

Він не є шляхом файлової системи Windows. Перша частина відповідає директиві `module`, а `module-demo/greeting` — каталогу пакета всередині модуля.

## Запуск

Перейдіть до каталогу `examples` і виконайте:

```powershell
go run ./module-demo
```

Очікуваний результат:

```text
Вітаємо, студент!
```

Для Bash або zsh команда така сама.

## Тести

Лише пакет `greeting`:

```powershell
go test -v ./module-demo/greeting
```

Усі пакети модуля:

```powershell
go test ./...
```

Тест передає ім’я з пробілами й перевіряє, що `Build` їх прибирає. Корисне самостійне доповнення — негативний тест для порожнього рядка або рядка лише з пробілів.

## Що змінити для експерименту

1. Замініть ім’я в `main.go` і повторіть запуск.
2. Передайте `"   "`, простежте обробку помилки.
3. Додайте тест порожнього імені.
4. Тимчасово змініть import path і прочитайте повідомлення компілятора, після чого поверніть правильний шлях.

## Типові помилки

- запуск із каталогу поза модулем;
- import за локальним шляхом на кшталт `C:\...`;
- назва `build` з малої літери, коли функцію потрібно викликати з іншого пакета;
- ігнорування поверненої помилки;
- створення окремого `go.mod` у кожному підкаталозі без потреби.
