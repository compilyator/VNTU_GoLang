# Приклад `clean-main`: предметна логіка й подання поза `main`

Приклад перетворює метри на сантиметри та навпаки. Його головна мета — показати межі відповідальності: `main` з’єднує компоненти, пакет `converter` виконує предметну операцію, а пакет `console` форматує результат.

> **Основна інструкція:** приклад розширює матеріал [«Структура невеликого консольного проєкту Go»](../../manuals/go-project-structure/). В інструкції пояснено, як проєктувати власні структури й інваріанти, визначати відповідальності пакетів, уникати циклічних залежностей і залишати `main` чистим. Не використовуйте нейтральну модель цього прикладу замість самостійного проєктування предметної моделі свого варіанта.

## Структура

```text
clean-main/
├── README.md
├── main.go
├── converter/
│   ├── converter.go
│   └── converter_test.go
└── console/
    ├── console.go
    └── console_test.go
```

### `main.go`

Читає прапорці `-value`, `-from`, `-to`, викликає предметний пакет, передає результат пакету подання й визначає реакцію на помилку. Він не містить формул перетворення та ручної побудови рядка результату.

### Пакет `converter`

- `Result` описує результат завершеної операції;
- `Convert` перевіряє значення й підтримувані пари одиниць;
- пакет не імпортує `os`, `flag` або пакет `console`;
- тест перевіряє предметний результат без запуску CLI.

### Пакет `console`

- `Render` приймає `io.Writer` і `converter.Result`;
- форматування відокремлене від обчислення;
- тест записує текст у `bytes.Buffer` замість реальної консолі.

Напрям залежностей:

```text
main ──→ converter
  └────→ console ──→ converter
```

`converter` не залежить від зовнішніх шарів, тому його легко повторно використати й перевірити.

## Запуск

Із каталогу `examples`:

```powershell
go run ./clean-main -value 2.5 -from m -to cm
```

Очікуваний результат:

```text
2.50 m = 250.00 cm
```

Зворотне перетворення:

```powershell
go run ./clean-main -value 250 -from cm -to m
```

Помилковий сценарій:

```powershell
go run ./clean-main -value -1 -from m -to cm
```

## Тести

Увесь приклад:

```powershell
go test -v ./clean-main/...
```

Окремо предметна логіка:

```powershell
go test -v ./clean-main/converter
```

Окремо подання:

```powershell
go test -v ./clean-main/console
```

## Що приклад навмисно спрощує

Це демонстрація структури, а не повний CLI-контракт. `main.go` не перевіряє факт явного передавання всіх прапорців і не має окремої функції `run`. Для лабораторної №3 ці частини потрібно спроєктувати відповідно до її вимог, а не копіювати приклад без змін.

## Експерименти

1. Додайте негативні тести для `converter.Convert`.
2. Змініть формат подання, не торкаючись пакета `converter`.
3. Додайте альтернативну функцію подання, що приймає той самий `Result`.
4. Поясніть, чому `console` може залежати від `converter`, але зворотна залежність була б проблемою.
5. Намалюйте аналогічну схему пакетів для власного проєкту, самостійно визначивши предметні типи й поля.

## Типові помилки

- перенесення формул у пакет `console`;
- друк результату безпосередньо з предметної функції;
- виклик `os.Exit` у бібліотечному пакеті;
- створення циклічного імпорту;
- надмірна кількість пакетів без окремої відповідальності;
- копіювання структури `Result` без адаптації до власної предметної області.
