# Приклад `writer-output`: виведення через `io.Writer`

Приклад формує нумерований текстовий список. Він демонструє, як відокремити створення виведення від конкретного місця призначення: консолі, буфера, файла або іншого потоку.

> **Основна інструкція:** цей приклад використовується в матеріалі [«Основи тестування програм Go»](../../manuals/go-testing-basics/) для пояснення перевірки виведення через `bytes.Buffer`. Архітектурну роль окремого пакета представлення додатково розглянуто в інструкції [«Структура невеликого консольного проєкту Go»](../../manuals/go-project-structure/).

## Структура

```text
writer-output/
├── README.md
├── main.go
└── main_test.go
```

- `renderList` приймає `io.Writer`, заголовок і зріз рядків;
- кожна операція запису перевіряється на помилку;
- `main` передає `os.Stdout` і окремо обробляє помилку виведення;
- тест передає `bytes.Buffer` та порівнює отриманий текст з очікуваним.

## Навіщо `io.Writer`

Функції не потрібно знати, куди саме підуть байти. Один контракт підтримують:

- `os.Stdout` і `os.Stderr`;
- `bytes.Buffer` для тесту;
- файл;
- мережеве з’єднання;
- складений потік на кшталт `io.MultiWriter`.

Це спрощує тестування й не прив’язує форматування до глобальної консолі.

## Запуск

Із каталогу `examples`:

```powershell
go run ./writer-output
```

Очікуваний результат:

```text
Етапи перевірки
1. форматування
2. тести
3. перегляд diff
```

## Тест

```powershell
go test -v ./writer-output
```

Тест створює порожній `bytes.Buffer`, викликає `renderList`, а потім порівнює `output.String()` з точним статичним очікуванням. Реальний `stdout` не використовується.

## Потік помилки

`fmt.Fprintln` і `fmt.Fprintf` повертають кількість записаних байтів та помилку. Для консолі помилка трапляється рідко, але загальний `io.Writer` може відмовити. Функція повертає першу таку помилку виклику, а `main` вирішує, як її показати й який код завершення повернути.

## Експерименти

1. Передайте порожній зріз і зафіксуйте бажаний контракт тестом.
2. Перевірте заголовок із пробілами або символами Unicode.
3. Створіть у тесті власний `io.Writer`, який завжди повертає помилку, та переконайтеся, що `renderList` її не приховує.
4. Додайте інший формат виведення окремою функцією.
5. Спробуйте `io.MultiWriter(os.Stdout, &buffer)` у маленькому експерименті.

## Типові помилки

- використання `fmt.Println` усередині функції, яку треба тестувати;
- ігнорування помилки `Fprintf`;
- змішування предметних обчислень із форматуванням;
- перевірка випадкового або залежного від часу тексту точним порівнянням;
- надмірно крихкий тест, який перевіряє несуттєві пробіли, коли формат не є частиною контракту.
