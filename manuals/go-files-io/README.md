# Файли та потоки в Go

**Мета:** читати обмежений обсяг даних і створювати нові файли без пошкодження наявних. **Передумови:** функції, помилки, інтерфейси. **Середовище:** Go 1.25 відповідно до модуля прикладів, Windows / PowerShell або Linux/macOS / Bash. Сторонні бібліотеки не потрібні.

Після практики ви зможете пояснити, від чого обчислюється шлях, перевірити межу читання й обробити відмову запису.

## 1. Поточний каталог і шляхи

Відносний шлях обчислюється від поточного робочого каталогу процесу. Він не обов’язково збігається з каталогом коду чи виконуваного файла. Перед запуском перевірте `pwd` і `ls`; шлях із пробілами беріть у лапки. У Go складайте шляхи через `filepath.Join`.

`os.Open` відкриває наявний файл для читання; після роботи його потрібно закрити. Повертайте помилки із контекстом операції та шляху. Якщо читання і закриття завершилися помилками, `errors.Join` дозволяє зберегти обидві.

## 2. Потік замість конкретного файла

`io.Reader` надає байти, `io.Writer` приймає їх. Функція, що отримує `io.Reader`, може працювати з файлом або `strings.Reader` у тесті. Не змушуйте декодер самостійно відкривати файл: це спрощує перевірку.

[Приклад виведення через `io.Writer`](../../examples/writer-output/) показує зворотний напрям. Під час `io.Copy` перевіряйте повернену помилку; `bufio.Scanner` також потребує перевірки `Err()` після циклу й окремого налаштування межі токена.

## 3. Обмежене читання

[Приклад `file-safety`](../../examples/file-safety/) читає не більше `limit+1` байтів. Якщо отримано додатковий байт, вхід завеликий. Читання лише `limit` байтів не дозволяє відрізнити точний розмір від обрізаного потоку. Попередня перевірка розміру файла не замінює перевірку фактично прочитаних даних.

У прикладі межа — 8 байтів, щоб її легко перевірити вручну. Для JSON-завантажувача обирайте межу за контрактом задачі. Байти та символи Unicode — різні одиниці.

## 4. Запис без перезапису

Спочатку підготуйте весь невеликий результат у пам’яті. Потім створіть файл через `os.OpenFile` з `os.O_WRONLY|os.O_CREATE|os.O_EXCL`. Окрема перевірка `os.Stat` перед звичайним створенням не гарантує відсутності перезапису між операціями.

У `writeNew` прикладу перевіряються кількість записаних байтів, помилка запису та помилка `Close`. При невдачі видаляється лише файл, створений цим викликом, і повідомляється також помилка прибирання. Наявний файл не видаляється. Відсутні батьківські каталоги не створюються автоматично.

Права `0o600` задають доступ власнику на Unix-подібних системах з урахуванням правил ОС; це не заміна налаштуванню Windows ACL. Приклад не гарантує відновлення після вимкнення живлення та не захищає від зловмисної заміни каталогів. Тимчасовий файл із перейменуванням — інша стратегія; її гарантії залежать від ОС і не тотожні забороні заміни наявного файла.

## 5. Запуск і перевірка

З каталогу `examples`, у PowerShell або Bash:

```text
go run ./file-safety
go test -v ./file-safety
```

Очікуйте прийняття 8 байтів, відхилення 9 і повідомлення про відмову від перезапису. Демонстрація працює у власному тимчасовому каталозі та прибирає його. Тести використовують `t.TempDir` і перевіряють, що оригінальний вміст залишився незмінним.

## Практика та LLM

1. У власній копії змініть межу на 12 байтів. Перед запуском запишіть очікування для 11, 12 і 13 байтів, потім перевірте їх.
2. Перевірте шлях із пробілами й відсутній батьківський каталог. Зафіксуйте фактичну помилку та стан файлів.
3. Попросіть онлайн-LLM пояснити, чому `Stat` перед записом недостатньо. Зіставте пояснення з кодом і документацією `OpenFile`; виправте неточності. Онлайн-діалогу достатньо для аналізу без доступу до диска.

Якщо залучаєте агента до тестів, дозволяйте зміни лише у власній копії прикладу й тимчасових каталогах. Перегляньте diff та самостійно повторіть запуск. У нотатках зазначте сервіс, модель, якщо відома, дату, мету, істотний запит, прийнятий результат, власні зміни й спосіб перевірки. Використовуйте лише вигадані дані.

## Типові проблеми й самоперевірка

- `file exists`: задайте нове ім’я; автоматичне видалення оригіналу порушує контракт.
- Файл не знайдено: перевірте поточний каталог і лапки.
- Обрізаний вхід прийнято: перевірте читання додаткового байта.
- Порожній або неповний результат: перевірте підготовку до відкриття файла та обробку помилок запису.

Чому `Close` може повернути помилку? Чому межа байтів не дорівнює межі символів? Які дані має зберегти тест після відхиленого перезапису?
