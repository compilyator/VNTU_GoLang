# HTML-звіт у Go: шаблон, тестові дані та готовий документ

**Мета:** поєднати HTML-шаблон із даними Go й отримати окремий звіт для локального перегляду. **Передумови:** структури, функції, помилки, JSON і файли. **Середовище:** Windows + PowerShell або Linux/macOS + Bash, Go, браузер, редактор. Приклад має `go 1.25` у `go.mod` і не використовує сторонніх бібліотек. Перевірено на Windows із Go 1.25.1 21.09.2026; це версія перевірки, а не твердження про найновіший випуск.

Результат — один HTML-файл із вбудованими стилями та фактичними даними. Його можна відкрити без сервера й інтернету. Необов’язковий скрипт додає кнопку друку; дані від JavaScript не залежать.

## 1. Три складові звіту

| Складова | Призначення | Приклад |
| --- | --- | --- |
| Вхідні дані | Факти, які потрібно перевірити й обробити | Обладнання, кількість, мінімальний запас |
| Модель представлення | Підготовлені показники та рядки | Загальна кількість, дефіцитні позиції, позначка стану |
| HTML-шаблон | Структура, стилі та місця підстановки | Заголовок, картки, таблиця |

```text
sample.json → декодування → валідація → обчислення в Go
                                               ↓
report.tmpl.html ─────────────────────→ html/template
                                               ↓
                                       буфер → report.html
```

Шаблон не обчислює предметну статистику. Він отримує готові значення та визначає їхнє відображення. Тому оформлення можна змінити без переписування аналізу.

Повний [виконуваний приклад](../../examples/html-report/README.md) містить [Go-код](../../examples/html-report/main.go), [дані](../../examples/html-report/data/sample.json), [шаблон](../../examples/html-report/report.tmpl.html), [готовий HTML](../../examples/html-report/sample-report.html) і [тести](../../examples/html-report/main_test.go).

## 2. Підготуйте репрезентативні дані

У прикладі обліковуємо обладнання вигаданої майстерні. Файл `data/sample.json`:

```json
{
  "title": "Обладнання навчальної майстерні",
  "location": "Майстерня «Обрій»",
  "observedAt": "2026-09-20T10:00:00+03:00",
  "items": [
    {"name": "Кабель USB-C", "quantity": 12, "minimum": 5},
    {"name": "Мультиметр", "quantity": 3, "minimum": 5},
    {"name": "Набір <навчальний> & запасний", "quantity": 0, "minimum": 2}
  ]
}
```

Набір охоплює достатню кількість, дефіцит і нульовий залишок. Назва з `<`, `>` та `&` допомагає перевірити HTML-екранування. До запуску порахуйте очікування: **3 найменування**, **12 + 3 + 0 = 15 одиниць**, **2 позиції для поповнення**. Кількість, рівна мінімуму, означає «Достатньо».

Час спостереження належить набору; час створення звіту визначається під час запуску. Не підміняйте один іншим.

## 3. Відокремте дані від представлення

У `main.go` структури `Dataset` та `Item` описують JSON. Поля `Quantity` і `Minimum` мають тип `*int`, щоб відрізнити допустимий нуль від пропущеного поля або `null`. Перед розіменуванням програма перевіряє вказівник на `nil`.

`buildReport` перевіряє дані й створює `Report`. Рядки `Row` вже містять звичайні числа та ознаку `Low`. Підсумки обчислюються в Go. Функція приймає час параметром: тест фіксує його й не залежить від годинника комп’ютера.

Правила нейтрального прикладу: 1–100 позицій, кількості 0–10000, непорожні назви, дата RFC 3339. Вони не задають обмежень лабораторної; для власного завдання застосовуйте його предметні правила.

## 4. Підготуйте HTML-шаблон

`report.tmpl.html` — HTML-документ із `lang="uk"`, UTF-8, адаптивним viewport, стилями в `<style>` та виразами `{{...}}`. Браузер сам не виконує ці вирази: спочатку шаблон обробляє Go.

| Конструкція | Значення |
| --- | --- |
| `{{.Title}}` | Поле `Title` поточного значення |
| `{{len .Rows}}` | Кількість рядків |
| `{{range .Rows}} ... {{end}}` | Повторення для рядків; крапка всередині означає поточний рядок |
| `{{if .Low}} ... {{else}} ... {{end}}` | Вибір відображення за логічною ознакою |

Фрагмент таблиці:

```html
<tbody>
  {{range .Rows}}
  <tr>
    <td>{{.Name}}</td>
    <td>{{.Quantity}}</td>
    <td>{{if .Low}}Поповнити{{else}}Достатньо{{end}}</td>
  </tr>
  {{end}}
</tbody>
```

Доступні шаблону поля структури мають бути експортованими, тобто починатися з великої літери. Тег `json:"title"` задає назву в JSON, але не перейменовує поле шаблону: використовуйте `.Title`, не `.title`.

Для моделі з полем `Average` форматування `{{printf "%.2f" .Average}}` показує два знаки після крапки. Це не причина округлювати первинні дані до аналізу.

CSS у прикладі задає картки, таблицю, вузький екран і друк. Стан передається також словами, а не лише кольором. Для автономного документа не підключайте зовнішні шрифти чи бібліотеки.

## 5. Виконайте шаблон у Go

Функція `renderReport` із прикладу:

```go
func renderReport(source string, report Report) ([]byte, error) {
    tmpl, err := template.New("report").Option("missingkey=error").Parse(source)
    if err != nil {
        return nil, fmt.Errorf("розбір шаблону: %w", err)
    }
    var output bytes.Buffer
    if err := tmpl.Execute(&output, report); err != nil {
        return nil, fmt.Errorf("виконання шаблону: %w", err)
    }
    return output.Bytes(), nil
}
```

Це фрагмент повної програми: потрібні імпорти `bytes`, `fmt`, **`html/template`** і тип `Report` із `main.go`. `Parse` перевіряє синтаксис. `Execute` підставляє дані й також може повернути помилку, наприклад через невідоме поле. `missingkey=error` додатково забороняє мовчазний пропуск відсутніх ключів map; невідоме поле структури й так спричиняє помилку.

Результат спочатку формується в `bytes.Buffer`. Лише після успіху програма створює файл, тому помилка шаблону не залишає половину HTML. Для великих звітів потрібна інша стратегія; тут обсяг даних обмежено.

`writeNew` використовує `os.O_EXCL`, перевіряє запис і закриття, прибирає новий неповний файл при помилці. Наявний звіт не замінюється. Це не повна транзакція й не гарантія відновлення після вимкнення живлення.

## 6. Запустіть приклад

Завантажте матеріали разом зі спільним модулем `examples`. Відкрийте термінал у каталозі `examples/html-report`; Go знайде `go.mod` у батьківському каталозі.

PowerShell:

```powershell
go version
go test ./...
go vet ./...
go run . --input data/sample.json --template report.tmpl.html --output report.html
Start-Process ./report.html
```

Bash (Linux/macOS):

```bash
go version
go test ./...
go vet ./...
go run . --input data/sample.json --template report.tmpl.html --output report.html
```

У Linux/macOS відкрийте результат через файловий менеджер або команду відкриття свого середовища. У будь-якій ОС можна скористатися командою браузера «Відкрити файл».

Очікувано: повідомлення `HTML-звіт створено: report.html`, у браузері — картки **3**, **15**, **2** і три рядки обладнання. Відкривайте результат, а не шаблон. Для другого запуску задайте новий вихід, наприклад `--output report-v2.html`. Наявний файл має залишитися незмінним.

Без прапорців використовуються `data/sample.json`, `report.tmpl.html`, `report.html`. Шляхи відлічуються від поточного робочого каталогу. Цей приклад не має підкоманди `analyze`: передавайте прапорці відразу після `go run .`, без додаткового `--`, який зупинив би розбір стандартним `flag`.

## 7. Стилі, скрипти й безпечні дані

Вбудований скрипт знаходить кнопку за фіксованим `id` і викликає `window.print()`. Кнопка початково прихована та з’являється лише з JavaScript. Скрипт не отримує JSON, не виконує запитів і не використовує `innerHTML`. Його можна прибрати без втрати змісту.

За документацією [`html/template`](https://pkg.go.dev/html/template), звичайні значення екрануються відповідно до контексту. Назва `Набір <навчальний> & запасний` залишається текстом. Захист передбачає **довірений шаблон і недовірені дані**: скрипт, який автор вписав у сам шаблон, не стає безпечним від використання пакета.

Переглядайте HTML/CSS/JS від LLM до запуску. Не вимикайте екранування через `template.HTML` чи `template.JS`. Не конкатенуйте назви з HTML і не вставляйте текстові поля у виконуваний JavaScript. Для базового звіту достатньо текстових вузлів і таблиць.

Завантажувач перевіряє межу 1 MiB, невідомі поля й відсутність другого JSON-документа; потім виконується предметна валідація. Навчальне спрощення: окремого пошуку повторюваних ключів JSON немає; для суворіших форматів обміну його потрібно розглядати додатково.

## 8. Перевірте зміст і вигляд

1. Порівняйте цифри з ручним розрахунком: 3, 15, 2.
2. У копії JSON змініть кількість мультиметрів із 3 на 5. Очікування: 17 одиниць і 1 позиція для поповнення. Сформуйте новий файл.
3. Перевірте довгу назву, `<`, `>` та `&`, нульовий залишок, широке й вузьке вікно. Для таблиці допустиме локальне горизонтальне прокручування.
4. Вимкніть мережу: звіт має бути повним. Без JavaScript усі дані залишаються, а кнопка друку не з’являється.
5. Перевірте наявний вихід і пошкоджений шаблон: попередній файл не псується, неповний HTML не створюється.
6. Запустіть `go test -v ./...`: перевіряються числа, екранування, некоректний JSON, розмір, шаблон і відмова від перезапису.

Тест HTML-ін’єкції підставляє локальний нешкідливий рядок `<script>document.title='НЕБЕЗПЕЧНО'</script>` у назву. Він має стати текстом, а не виконуваним елементом. Працюйте лише зі своїм локальним файлом. Причина потенційної вразливості — змішування розмітки з даними; захист — екранування. Після виправлення повторіть тест.

## 9. Спроєктуйте шаблон разом із LLM

Почніть з онлайн-діалогу: для обговорення аудиторії, полів і стилю доступ до файлів не потрібний. Перший запит:

> Я створюю локальний HTML-звіт про обладнання майстерні. Маю назву, місце, час спостереження, позиції з кількістю й мінімальним запасом, загальну кількість і число позицій для поповнення. Спочатку постав уточнювальні запитання про читача. Потім запропонуй два способи організації звіту: що показати картками, що таблицею, які пояснення додати. Не генеруй код до обговорення структури.

Після вибору:

> Створи український HTML-шаблон для Go html/template за погодженою структурою. Поля: Title, Location, ObservedAt, GeneratedAt, Total, LowCount, Rows; поля рядка: Number, Name, Quantity, Minimum, Low. CSS вбудований, зовнішніх залежностей немає. Дані читаються без JavaScript. Передбач довгі назви, нульові значення, вузький екран і друк. Не використовуй template.HTML і не вигадуй показників.

Обговоріть результат: чи видно час спостереження, чи зрозумілі одиниці, чи не замінює колір текстовий стан, чи немає статичних чисел. Попросіть пояснити незнайомі CSS-властивості й конструкції шаблону. Обґрунтуйте власні зміни.

Агенту для реалізації дозволяйте змінювати лише власну копію навчального прикладу й запускати локальні тести. Переглядайте diff; не передавайте персональні дані чи секрети. У журналі зазначте сервіс, модель, якщо відома, дату, мету, істотні запити, використаний результат, власні виправлення та перевірки. Для лабораторної додатково дотримуйтеся її вимог до Git.

## 10. Типові проблеми

| Симптом | Причина та дія |
| --- | --- |
| Видно `{{.Title}}` | Відкрито шаблон; виконайте Go-програму й відкрийте вихідний HTML |
| `can't evaluate field` | Неправильна назва поля або контекст усередині `range` |
| `file exists` | Використайте нове ім’я виходу |
| Дані не знайдено | Перевірте `pwd`, каталог `data` й лапки в шляхах із пробілами |
| Стилі зникають без інтернету | Приберіть зовнішні залежності, вбудуйте CSS |
| Назва стала HTML-елементом | Перевірте імпорт, приведення типів і ручне складання HTML |
| Числа не змінюються | У шаблоні залишено статичні дані замість полів |
| Змінився час | Новий час формування допустимий; первинний час спостереження має зберігатися |
