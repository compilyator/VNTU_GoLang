# Як перевіряти алгоритм і результати програми

Запуск без аварії ще не доводить правильність алгоритму. Ця інструкція описує відтворювану перевірку: від формулювання контракту до автоматичних тестів і пояснення результату на захисті.

## 1. Сформулюйте контракт

До написання коду запишіть:

- **вхідні дані** — тип, формат, допустимий діапазон;
- **передумови** — що має бути істинним перед викликом;
- **результат** — що саме повертає алгоритм;
- **післяумови** — властивості коректного результату;
- **помилки** — які неправильні дані відхиляються;
- **побічні ефекти** — чи змінюється вхідний зріз, файл або стан.

Приклад нейтральної післяумови сортування: кількість елементів не змінюється; кожен початковий елемент зберігається; сусідні елементи розташовані за визначеним правилом.

## 2. Виберіть малий статичний набір

Для лабораторної переважно використовуйте явно записані дані:

```text
8, -3, 8, 0, 15, -3
```

Набір має бути достатньо малим для ручного обчислення і достатньо різноманітним для помилок: повтори, нуль, від’ємні та додатні значення. Не підганяйте дані під один очікуваний результат.

Якщо алгоритм працює зі структурами, дайте кожному запису короткий штучний ідентифікатор. Не використовуйте реальні персональні дані.

## 3. Обчисліть очікування незалежно

Складіть таблицю:

| Сценарій | Вхід | Очікуваний результат | Чому саме так |
|---|---|---|---|
| звичайний | невеликий змішаний набір | обчислено вручну | основне правило |
| межовий | один елемент | визначений результат | мінімальний непорожній набір |
| некоректний | заборонене значення | помилка | порушена передумова |

Очікуване значення не можна отримувати копією того самого алгоритму: дві однакові помилки дадуть хибне відчуття правильності. Для малого набору використайте ручний підрахунок або простіше незалежне правило.

## 4. Трасування

Для циклу або послідовного алгоритму запишіть стан після кожної ітерації:

| Крок | Поточний елемент | Стан накопичувача | Прийняте рішення |
|---:|---:|---:|---|
| 0 | — | початкове значення | ініціалізація |
| 1 | перший | новий стан | пояснення умови |

Трасування особливо корисне для пошуку помилки межі циклу, неправильного початкового значення та пропуску першого чи останнього елемента.

## 5. Класи й межі

Розділіть можливі входи на класи, у яких поведінка однакова. Перевірте представника кожного класу та межі між ними:

- порожній набір;
- один елемент;
- два елементи в правильному і зворотному порядку;
- усі елементи однакові;
- повтори серед різних значень;
- уже впорядкований і зворотно впорядкований набір;
- мінімальне, максимальне й сусіднє значення допустимого діапазону;
- неправильний формат або значення поза діапазоном.

Не всі пункти потрібні кожній функції. Обирайте ті, що випливають із контракту.

## 6. Перевірка властивостей

Іноді точний результат великий, але його властивості перевірити легко. Для сортування перевірте порядок і збереження елементів. Для фільтрації — що кожен результат задовольняє умову, а жоден допустимий елемент не втрачено. Для перетворення — одиниці вимірювання та можливість перевірити кілька еталонних пар.

Перевірка властивостей доповнює, але не завжди замінює приклади з точним очікуваним результатом.

## 7. Дублікати як приклад вибору алгоритму

Простий пошук повторів двома вкладеними циклами має квадратичну складність `O(n²)`. Підрахунок частот через `map` зазвичай потребує `O(n)` часу й `O(n)` додаткової пам’яті. Обираючи підхід, поясніть компроміс, а не лише назву складності.

Якщо результат виводиться з `map`, порядок не гарантовано. Для відтворюваного звіту перенесіть ключі у зріз і відсортуйте їх перед виведенням.

## 8. Стабільність і детермінованість

Однаковий вхід має давати однаковий результат, якщо випадковість не є частиною умови. Якщо використовуєте генератор, створіть локальний генератор із фіксованим `seed` та збережіть його значення. Для основної перевірки лабораторної кращий статичний набір.

Врахуйте джерела нестабільності: порядок обходу `map`, поточний час, локаль, мережевий сервіс, паралельне виконання та спільний глобальний стан.

## 9. Від ручної перевірки до тесту

1. Запишіть контракт.
2. Доберіть статичний набір.
3. Обчисліть очікування вручну.
4. Зробіть трасування складного випадку.
5. Перенесіть сценарії в табличний тест.
6. Додайте негативні та межові випадки.
7. Навмисно внесіть малу помилку й переконайтеся, що тест її знаходить.
8. Поверніть правильний код і повторіть `go test ./...`.

## 10. Що показати у звіті

- вихідний статичний набір;
- обґрунтування вибраних випадків;
- ручний очікуваний результат;
- за потреби — таблицю трасування;
- автоматичні тести та результат їх запуску;
- знайдену помилку або пояснення, яку помилку виявляє кожен тест;
- для генератора — фіксований `seed` і спосіб відтворення.

## Контрольний список

- [ ] контракт не суперечить реалізації;
- [ ] є звичайний, межовий і помилковий сценарії;
- [ ] очікування отримано незалежно від тестованої функції;
- [ ] тест відтворюється на іншому комп’ютері;
- [ ] порядок результату визначений або не перевіряється безпідставно;
- [ ] зрозуміло, чи змінюється вхід;
- [ ] складність алгоритму пояснено на рівні, потрібному для задачі.
