# Консольне введення і валідація в Go

Консольне введення є недовіреним: користувач може ввести порожній рядок, пробіли, текст замість числа, число поза діапазоном, надто довгий текст або завершити потік до очікуваного значення.

## Розділяйте читання, parsing і предметну перевірку

```text
байти stdin
→ читання рядка
→ TrimSpace
→ parsing у потрібний тип
→ перевірка діапазону й предметних правил
→ використання значення
```

Помилка формату `abc` відрізняється від числа `101`, яке має правильний формат, але виходить за дозволену межу.

## `bufio.Scanner`

`Scanner` зручний для коротких рядків:

```go
scanner := bufio.NewScanner(os.Stdin)

if !scanner.Scan() {
	if err := scanner.Err(); err != nil {
		return fmt.Errorf("помилка читання: %w", err)
	}
	return errors.New("введення завершилося раніше, ніж очікувалося")
}

text := strings.TrimSpace(scanner.Text())
```

- `Scan()` повертає `true`, якщо отримано token.
- За замовчуванням token є рядком без завершального переносу.
- `Text()` читають лише після успішного `Scan()`.
- Після `false` потрібно перевірити `Err()`: EOF і помилка читання — різні ситуації.

`Scanner` має ліміт token size. Для коротких навчальних параметрів краще додатково встановити власну предметну межу, наприклад 100 символів, а не дозволяти довільні мегабайти.

## `bufio.Reader`

Для явного читання до переносу:

```go
reader := bufio.NewReader(os.Stdin)
line, err := reader.ReadString('\n')
if err != nil && !errors.Is(err, io.EOF) {
	return fmt.Errorf("помилка читання: %w", err)
}

line = strings.TrimSpace(line)
```

За EOF `ReadString` може повернути і дані, і `io.EOF`. Не відкидайте прочитаний фрагмент автоматично.

## Чому не варто змішувати `fmt.Scan` і читання рядків

`fmt.Scan` читає token, розділений пробілами, тому назва `New York` перетвориться лише на `New`. Крім того, залишений у потоці символ переносу може спричинити несподіваний порожній рядок при наступному `ReadString`.

Для однієї форми введення використовуйте одну послідовну модель: читати повні рядки, очищати їх і явно перетворювати.

## Parsing чисел

Ціле число:

```go
text := strings.TrimSpace(line)
count, err := strconv.Atoi(text)
if err != nil {
	return fmt.Errorf("кількість %q не є цілим числом: %w", text, err)
}
```

`float64`:

```go
value, err := strconv.ParseFloat(text, 64)
if err != nil {
	return fmt.Errorf("значення %q не є числом: %w", text, err)
}
```

- `Atoi` повертає `int`.
- `ParseFloat(..., 64)` повертає `float64`.
- У програмному форматі десятковим роздільником є крапка, якщо умова не визначає окремий locale-aware parsing.
- Не ігноруйте помилку через `_`.

## Перевірка діапазону

```go
if count < 5 || count > 100 {
	return fmt.Errorf("кількість має бути від 5 до 100, отримано %d", count)
}
```

Спочатку parse, потім range check. Не порівнюйте числові рядки лексикографічно.

Для двох пов'язаних значень:

```go
if minimum > maximum {
	return errors.New("нижня межа не може перевищувати верхню")
}
```

## Текстовий параметр із кількох слів

```go
subject := strings.TrimSpace(line)
if subject == "" {
	return errors.New("предметний параметр не може бути порожнім")
}
if utf8.RuneCountInString(subject) > 100 {
	return errors.New("предметний параметр довший за 100 символів")
}
```

`len(subject)` рахує байти, а `utf8.RuneCountInString` — Unicode code points. Для суворого обмеження користувацького тексту поясніть, яку саме одиницю ви обрали; rune не завжди дорівнює видимому grapheme cluster.

## Повторне введення

Повторення доречне лише тоді, коли це визначено контрактом програми. Цикл має мати зрозумілий спосіб завершення:

```go
for attempts := 1; attempts <= 3; attempts++ {
	value, err := readCount(scanner)
	if err == nil {
		return value, nil
	}
	fmt.Fprintf(stderr, "Спроба %d: %v\n", attempts, err)
}
return 0, errors.New("вичерпано кількість спроб")
```

Нескінченний цикл `for {}` без коректної обробки EOF може безкінечно друкувати одну помилку після закриття stdin.

## Функція не повинна залежати від клавіатури

Замість жорсткого `os.Stdin` прийміть `io.Reader`:

```go
func readRequest(reader io.Reader) (Request, error) {
	scanner := bufio.NewScanner(reader)
	// читання і перевірка
}
```

У `main`:

```go
request, err := readRequest(os.Stdin)
```

У тесті:

```go
request, err := readRequest(strings.NewReader("5\nDemo label\n"))
```

Це не mock framework, а звичайна композиція через стандартний інтерфейс.

## Таблиця негативних перевірок

| Введення | Очікування |
| --- | --- |
| `5` | нижня дозволена межа приймається |
| `100` | верхня дозволена межа приймається |
| `4` | помилка діапазону |
| `101` | помилка діапазону |
| `0` | помилка діапазону |
| `-1` | помилка діапазону |
| `five` | помилка формату |
| порожній рядок | помилка формату або обов'язкового поля |
| лише пробіли | помилка після `TrimSpace` |
| `New York` | зберігаються обидва слова |
| передчасний EOF | контрольована помилка, не panic і не цикл |

## Потоки

- Запрошення й звичайний результат спрямовуйте в `stdout`.
- Діагностику помилок — у `stderr`.
- Не друкуйте помилку всередині кожної малої функції: поверніть її до рівня, який відповідає за взаємодію з користувачем.

## Типові помилки

- використання `fmt.Scan(&subject)` для багатослівної назви;
- продовження обчислень після помилки parsing;
- `panic` через звичайне неправильне введення;
- перетворення помилки на нуль і прийняття нуля як справжнього значення;
- однакове повідомлення для формату й діапазону;
- повторне створення нового reader для кожного поля;
- друк справжніх секретів або повного приватного шляху в діагностиці.

## Самоперевірка

- [ ] Повні рядки з пробілами читаються коректно.
- [ ] Порожній і whitespace-only текст відхиляються.
- [ ] Format validation відокремлена від range validation.
- [ ] EOF не спричиняє panic або нескінченний цикл.
- [ ] Reader можна замінити на `strings.NewReader` у тесті.
- [ ] Помилки повертаються, а не приховуються.
